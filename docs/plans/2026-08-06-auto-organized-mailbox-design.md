# 자동 정리함 설계

## 이해 요약

- AI 분석에 동의한 사용자의 받은편지함 메일을 선호도에 따라 자동 정리한다.
- 선호 가능성 40% 미만이며 신뢰도가 사용자 설정 이상인 메일만 대상으로 한다.
- 신뢰도 기본값은 70%이며 사용자가 50~100% 범위에서 5% 단위로 조절한다.
- Gmail에 `싹메일 자동정리함` 라벨을 만들고 대상 메일에서 `INBOX`만 제거한다.
- 자동 정리된 메일은 원본을 보존하며 받은편지함 복원, 휴지통 이동, 영구 삭제를 제공한다.
- 조회당 받은편지함 최대 20건만 평가하며 별도 스케줄러는 추가하지 않는다.

## 가정과 비기능 요구사항

- Gmail 라벨 생성과 메일 이동은 재실행해도 같은 결과가 되는 방식으로 구현한다.
- AI 분석이나 Gmail 변경에 실패한 메일은 받은편지함에 남긴다.
- 사용자 설정과 자동 정리 이력은 사용자 해시 키로 분리한다.
- 자동 정리 기준 변경은 다음 평가부터 적용하며 이미 이동된 메일은 자동 복원하지 않는다.
- 새 의존성은 추가하지 않고 기존 Gmail, D1, Workers AI 경로를 재사용한다.

## 결정 로그

1. 앱 내부 가상 보관함 대신 Gmail 사용자 라벨을 사용한다. Gmail과 싹메일에서 같은 상태를 보고 복원할 수 있기 때문이다.
2. 예약 Worker 대신 받은편지함 조회 시 평가한다. 현재 최대 20건 규모에 별도 스케줄러가 필요하지 않기 때문이다.
3. 삭제 대신 `INBOX` 제거와 사용자 라벨 추가를 사용한다. 사용자가 확인하기 전 원본을 보존하기 위해서다.
4. 선호도 기준은 40% 미만으로 고정하고 신뢰도만 사용자 설정으로 노출한다. 자동화 범위를 단순하고 예측 가능하게 유지하기 위해서다.

## 최종 설계

받은편지함 API는 Gmail 메일을 가져온 뒤 사용자 설정을 읽고 각 메일의 기존 추천 경로를 실행한다. 조건을 만족하면 `싹메일 자동정리함` 라벨을 조회하거나 생성한 뒤 메일에 해당 라벨을 추가하고 `INBOX`를 제거한다. 응답에는 이동되지 않은 메일만 반환한다.

자동정리함 API는 Gmail 사용자 라벨의 메일을 조회한다. 사용자는 개별 메일을 받은편지함으로 복원하거나 기존 휴지통·영구 삭제 기능을 실행한다. 복원은 `INBOX`를 추가하고 자동정리 라벨을 제거한다.

설정 API는 기존 동의 응답에 자동 정리 활성화 여부와 신뢰도 기준을 포함한다. 기본은 활성화, 70%이며 입력은 50~100의 5% 단위만 허용한다.

## 테스트 전략

- 설정 기본값·범위·단위 검증과 저장
- Gmail 라벨 조회·생성·이동·복원의 요청 계약
- 선호도 40% 및 사용자 신뢰도 경계값
- AI/Gmail 실패 시 받은편지함 유지
- 자동정리함 목록·복원·삭제 UI 상태
- 웹과 모바일 API 경로 동등성
